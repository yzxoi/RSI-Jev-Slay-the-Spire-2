# 研究进展与 Decision Record

## 2026-10-02 · D010 · 用户授权：增加自然数据并重训，先固定容量

[E133 / PR #251](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/pull/251) 保持 73,794 参数 S 网络、编码与 PPO/奖励不变，用 192 train / 24 val / 48 test 独立 seed，按序均分 Ironclad A0/A5/A10。每份 learner 1701/1702 最多 32×192=6,144 场，四倍 E127 单模型 episode 数；两份最多 12,288 场。采用原生战前存档降低重复恢复成本。

- 数据：264 seed 自然推进到首个精英/Boss 或第八战；224 到达边界、40 途中正常战败，保留所有 1,460 个入口。训练轮换每个 seed 的第一、第二、最后入口，共 575 个不同入口，其中 151 Elite、423 Monster、1 Boss，覆盖三类精英。192/191/192 分属 A0/A5/A10，423 deck hashes，198 携带药水。
- 顺序：先冻结银行并验证训练/验证入口恢复，再训练；只按固定验证集选 <=1,536 场与 <=6,144 场两个预算下的权重，提交哈希后才进行 48-seed 测试与完整前缀重放。较长预算可以选同一个早期 checkpoint，不强迫报告后期进步。
- 对照：旧 E127 S、程序规划器、攻击优先、本轮早期 checkpoint；分别报告早期/困难入口及难度。数据覆盖与训练量同时改变，因此本轮不是单独归因课程的 E131 实验。
- 当前状态：准备完成，存档认证中；尚无训练或强度结果。单 learner 最多 3,600 秒采样/优化，实际训练不完整批次跳过梯度并停止。只有达到预注册的未知 seed 强度门槛才继续扩张，不以 loss 下降替代结果。[协议](../../../experiments/E133/README.md)。

## 2026-10-02 · D009 · 结果：战前存档可复用；修正 E128 未接入现有加速的遗漏

[E132 / PR #249](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/pull/249) 用两个固定 seed × A0/A5/A10 自然推进：5/6 得到精英入口，A0-b 路线到 Boss，保留且不替换。五个入口的 40 次完整续演检查全部一致，包含奖励、下一战抽牌与真实战败；111 份原始 trace 哈希通过。15 组配对恢复中位数 4.507→1.172 秒，配对加速中位数 3.787×，p95 5.061→1.331 秒。[完整记录与复用 API](../../../experiments/E132/README.md)。

- 决定：保留可选存档库与验证工具；可用入口的精确性和本轮速度门槛通过，完整性门槛失败（5/6），不改默认游戏策略。优先为后续训练/搜索统一战前 reset，E129 常驻进程仍未执行。
- 纠正：E121 已证明原生 Map 存档可用，E124 也用过；E128 没为新的入口库生成存档，沿用完整历史重放。这是基础设施接入遗漏，不能解释为引擎没有存档能力。
- 边界：当前原生存档在真实 Map 边界可靠；战中保存不是任意状态克隆。内部节点用战前存档＋本场动作短前缀恢复。加载仍约一秒，主要在 load_save，单纯省进程启动收益有限。
- 数据：五个入口都是 Phrog Parasite，只有两个基础 seed，三种难度彼此相关。不可当宽泛训练覆盖或独立胜率证据。同一个 seed 的各难度/分支应留在同一数据划分。此轮没有新训练或整局胜率结论。

## 2026-10-02 · D008 · 结果：当前 PUCT 配置不值得推广，先解决恢复与危险状态覆盖

[E128 / PR #244](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/pull/244) 已完成 24 个固定 seed × 两个冻结大模型 × 两种叶节点评估，共 96 场。value 与终局 rollout 在 learner 1701 均为 21 胜 / 1 负 / 2 超时，1702 均为 22 胜 / 1 负 / 1 超时。直接 actor 两份各 22 胜 / 2 负，无超时。90 条完成方案独立重放一致，5,880 份 trace 哈希审计通过；强度与效率门槛均失败。[完整记录与图](../../../experiments/E128/README.md)。

- 决定：停止本轮扩训与搜索预算扩张；保留可选工具、修复与负结果，不替换默认实战策略。PPO 训练与固定模型搜索评估已经完成；预算修复的验证入口复测四场通过，与原 v1 全部转移及探测哈希一致；这只验证实现，不改变强度结论。
- 收益：已完成样本的配对 HP 中位数全部为 0；1702 rollout 有五例 +1～4 HP，其余 18 例持平，但尚有一例未完成。不能用条件样本推断全体收益。
- 成本：单场中位数 116～156 秒，对比直接 actor 约 2.6 秒；value 探测约 97% 用于恢复。恢复包含新局初始化与历史重放，不能只优化进程启动。
- 估值：两个 rollout 臂分别有 68/78、71/84 个实际死亡续演叶节点被预测为正回报。不同分支样本相关，且这表示当前 actor 续演死亡，不等于该局面所有策略必死。E127 的唯一合法 end_turn 例子则可以精确判断。
- 覆盖：192 个不同训练入口仅一个精英；测试精英 Bygone Effigy 未见于训练入口。该缺口与有损编码都值得检验，不能把扩参后的失败简单归因参数太少。
- 新提案：[E131 困难入口覆盖对照](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/issues/247)，与 E129 恢复、E130 强制终局分开。三者均未执行。仅在单场改善获得新 seed 证据后，才进入搜索改进策略训练与整局资源规划。

## 2026-10-02 · D007 · 结果：扩参未通过；精确终局应覆盖错误的 value

E127 已完成 6,144 场训练、100,932 动作。独立的 24 个测试 seed 上，S 两份各 23/24，L 两份各 22/24，规划器 23/24，攻击优先 21/24。L 对同初始化 S 的配对 HP 中位数均为 0，容量与扩训门槛都未通过。96 条所选模型轨迹独立重放一致，6,888 份 trace bundle 哈希通过。[完整记录与曲线](../../../experiments/E127/README.md)。

- 决定：停止本轮扩训，保留可选研究工具与负结果；E128 继续既定的固定模型搜索对照，不更换默认游戏策略。
- 具体缺口：在一个 Bygone Effigy 测试入口，两个大模型最后都只剩 end_turn 一个合法动作，随后真实死亡；value 仍预测 0.69/1.13，真实回报为 -1。不能用训练 MSE 小替代危险状态检验。
- 新提案：[E130 强制动作链精确续演](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/issues/246)，尚未执行。[E129 常驻引擎重置](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/issues/245)针对搜索的恢复瓶颈，也尚未执行。
- 结论边界：这不是证明大模型或 PPO 无效。S 扩训比 E125 多赢一个入口，但训练数据分布和预算同时改变，不能单独归因长训。不同模型的 value MSE来自不同策略路径，不是配对状态的因果比较。

## 2026-10-02 · D005 · 结果：PPO 能学习，但尚未超过强的简单基线

[E125 / PR #239](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/pull/239)：两个 7.4 万参数模型各训练 384 场，从验证集选定后，各通过 16 个未见 seed 的首战。均比规划器多损失中位数 6 HP，未达到 -5 HP 容忍门槛。32 个方案精确重放，1,000 份 trace bundle 哈希核对通过。

- 决定：合入可选训练/评估工具及负结果，停止当时的自动扩训，不能宣称 PPO 已优于规则。
- 推断：两个 PPO 的 Defend 都仅 7 次，而规划器 31 次，可能主要学到了进攻优先。不同策略走过的状态不同，不能单凭出牌计数认定漏防御。

## D004 · 结果：更多搜索预算的收益有限

[E120 #231](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/pull/231) 在十个 A0 精英入口中，规则 8/10、均匀 MC 与 UCT 各 9/10；恢复约占 81%，显式动作树仅两层。[E121 #235](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/pull/235) 的合法地图存档恢复通过精确性检查，但保守性能门槛未通过。[E124 #237](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/pull/237) 研究性启用后，同量 24 次搜索约 93→46 秒；提高到最多 64 次/120 秒，仍各 9/10，资源提升中位数为零。

决定：保留工具，不默认扩大预算或认定 UCT 胜过均匀 MC。优先改进分支评估与有效状态覆盖。研究快照的正确性与性能推广分开。

## D002 · 结果：专家建议与可靠执行是不同问题

[E099–E103](../../../README.md)：两个开发 Boss 局面中，持续 Astra 接管强于 Jev 自主执行；程序用药约束和引擎确认斩杀有局部收益。逐回合建议仍发生忽略防御、剩能量结束回合。动作约束可以保证落实已知计划，不能自动创造正确计划。

决定：确定性规则交程序，专家用于策略和困难局面；自动路由需独立验证质量/费用，不能只因模型便宜就固定 Jev。Astra 成本未完整计量时不宣称低成本优势。
