# E068 — review funded native shop exits

Issue: [#128](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/issues/128). Baseline: merged `main` `bc095f32f368fd2b127648fb9b57f1707d693151`. E065's real Ironclad A0 run left a floor-20 shop with 305 gold and three affordable relics, then died on floor 33 holding 444 gold. E066 did not establish that forcing a relic purchase improves wins; a narrower, opt-in Astra review avoids forcing an item and is reserved for a rare, high-value decision.

Hypothesis: if Jev proposes `close_shop_inventory` or `proceed` from an open shop with at least 250 gold, no purchase there and an affordable relic, the native controller should pause before delivery and hand the fresh legal options to Astra. A committed state-bound expert choice may buy or leave; after a purchase or closed inventory, Jev resumes. Default controller behavior remains unchanged. No HP, reward, RNG or victory edits.

Test that only the eligible exit requests review, no `act` RPC is issued at that boundary, and a shop purchase/explicit choice bypasses duplicate review. Then use `--review-funded-shop` in one fresh visible Ironclad A0 attempt with the current native controller flags, bounded segments and raw trace hashes; record its actual outcome, whether success or defeat. This one run cannot estimate win rate.

Decision rule: merge only if the frozen checks and project tests pass, the controller stops before any eligible exit with zero uncertain native delivery, and an actual state-bound expert choice can resume if the run reaches such a shop. If the visible attempt never reaches the trigger, report native strength as untested rather than inventing a purchase benefit. Keep strategy outcome and execution compatibility separate.
