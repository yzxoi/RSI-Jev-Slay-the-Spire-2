# E041 — Room-start Astra opener and Jev execution

Issue #73. E040 showed state-bound floor prose can reach Jev and finish a real elite, but it held three legal potions through a 26-HP hit and reached 1 HP. The actual elite was unknown at the map boundary. Test a more concrete division: after a forced map transition, Astra sees the actual combat state and commits one exact opening action plus compact room guidance. The controller maps the opener to a fresh legal candidate once, then Jev chooses subsequent actions. No stale or uncertain opener is repeated.

Baseline: the merged optional E040 `floor_guided` protocol and default `retaliate` controller. This single unreset native combat is a compatibility and decision trace, not a paired win-rate comparison. Do not infer that one opening potion/action would have improved the earlier elite fight.

Fixed input: `EFUZ4NHFCXBT` Ironclad A0, floor 11 MAP, 7/80 HP, 169 gold, one available Monster node. First enter it with one normal forced map action under the merged controller, maximum 1 action / 30 seconds / $0.01 Jev. Stop before choosing any combat action. Freeze full initial combat state locally and a public compact room plan before implementation evaluation. Then at most 80 accepted actions / 300 controller seconds / $0.10 Jev, stopping at the next MAP after rewards, normal defeat/victory, or a genuine safety/compatibility boundary. No reset, HP edit, reward injection or simultaneous game writer.

Protocol: bind plan to run ID, floor, COMBAT screen and exact state fingerprint. The opener must match a fresh currently legal candidate, otherwise stop without issuing it. After one accepted opener, do not replay it. Each later discretionary Jev request carries guidance and current computed proposal. Preserve the existing legal-action freshness checks and lethal-end-turn guard. Tests cover stale plan rejection, opener selection and single execution, and room boundary. Record game/MCP/model versions, code SHA, command, local trace hash, HP/resource changes, cost and latency.

Decision: promote only an opt-in protocol if unit checks pass, the pilot safely executes or explicitly rejects the opener, the stop boundary is honored, and actual combat result is reported. No default strength promotion from one fight. If guidance still fails to manage resources, retain that negative result and test game-engine-backed potion values as a separate idea.
