# E062 — Exoskeleton per-hit cap in combat planning

Issue: [#116](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/issues/116). Hypothesis: `HARD_TO_KILL_POWER` amount 9 caps each attack hit at 9 HP damage. The current planner models `SLIPPERY_POWER` but treats a displayed 24-damage Perfected Strike as 24 against this enemy, overvaluing expensive single hits relative to repeated cheap hits. E059 native floor 31 observed a displayed 14-damage Unrelenting remove 9 HP, a displayed 24-damage Perfected Strike remove 9 HP, and a 5×2 Fight Me remove 10 HP. Exact source code SHAs, state hashes and verified raw trace hashes are frozen in [`frozen-native-hits.json`](frozen-native-hits.json). This file is a sanitized observed-delta fixture, not a simulated engine state.

Baseline: merged main `0926445e779c29836ef9ac699babd964c3cb0f0a`. The treatment adds a per-hit cap to the approximate planner and native adapter; it does not alter the game or legal actions. For actual headless-engine paired evaluation, fix seeds `e062_cap_001`–`e062_cap_004`, Ironclad and Silent, A0 and A10, baseline `planfixed` against optional `planfixed_hitcap`: 16 pairs/32 episodes, at most 1,500 actions or 180 seconds each, three workers, no model calls. Pin game v0.111.0, sts2-cli `084d1aa3d8e118ca7ce8d8774ad16d6be9c92367`, dotnet SDK 9.0.318. Report every run, including errors/stalls, act/floor/win, capped-state exposure and treatment action divergence, with each raw trace hash. The headless policy is only an experimental comparator; the native adapter needs separate visible evaluation.

Decision rule: promote the deterministic correction only if it matches the three observed HP deltas, synthetic per-hit/multi-hit/block controls and full tests, and the headless batch has no execution regression or obvious unsafe divergence. If the natural cohort does not reach capped encounters, label strength evidence coverage-limited; do not infer win-rate gain. A blocked target's exact engine damage ordering is not established by the unblocked native observations, so synthetic block controls are internal-consistency checks, not native parity proof.

This mechanism is an **inference** from the relic text and transitions; the planner currently lacks that relic trigger. It warrants a separate issue and experiment.

Decision: **do not promote E062**. The cap arithmetic matches the observed hits, but the one natural decision divergence violated the preregistered no-obvious-harm condition. Close the PR with the failed branch and results accessible. Revisit cap-aware choice only after separately testing the missing Letter Opener trigger and other interactions. The 16 pair ties and zero wins do not establish a win-rate benefit.
