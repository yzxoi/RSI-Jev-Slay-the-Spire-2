# E047 — Reserve energy for retained Toxic at lethal HP

Issue #84. Hypothesis: a narrow deterministic guard can prevent Jev from spending the energy needed to play retained Toxic cards when their known five-damage end-turn effects plus visible enemy attacks would kill the player. It should reduce avoidable lethal action sequences without extra Astra calls. This offline candidate-filter evaluation does **not** establish that E045 would have survived or won; no game state is replayed or edited.

The simple baseline is E046's native `ordinary_candidates` guard at main SHA `e8ccf125cf72e831bbcce63a831b22f7482359bf`: it filters only dominated basic end turns and otherwise exposes all legal candidates. The E045 Myte turn2 trace shows 7 HP, 3 energy, two playable 1-cost Toxic cards (five end-turn damage each), a 13-damage enemy, Cloak Clasp and three Plating. Jev spent all three energy on attacks; the normal run lost at floor23. `frozen-mytes.json` stores two sanitized measured native states and their actual candidate lists: turn2 start fingerprint `0b010e40fed53a2cb2bd3affdcc61dd46c3467ca90055186f9dfa46fc594bfe8` and after Molten Fist fingerprint `a1c7fca73da20276b37a15914fdb7f3a44ee9b5932d61d86539853b897508fa8`. Source raw trace SHA-256 `848c53a92a5a4f0e075f74db577824ccccabdf3c8157d5b4861a7d286cece2b0`, ignored under `artifacts/runs/`. Any after-one-Toxic control is **synthetic**; it did not occur in E045.

Baseline command: `python3 - <<'PY'` with `ordinary_candidates` on the two fixture cases, using `floor_guided`; the exact command and output are in `baseline.json`. At main SHA above, both states kept every candidate: 13/13 at turn2 start, 11/11 after Molten Fist. Existing `filter_end_turn` abstained due unknown `PLATING` power. Both MCP `powers/PLATING_POWER` and `relics/CLOAK_CLASP` metadata explicitly say they grant block at end of turn; `cards/TOXIC` says it deals five damage if retained at end turn. The guard must not pretend Plating is absent.

Frozen evaluation inputs and decision rule: in the measured after-Molten state, only the two Toxic plays should remain if their energy reservation is required for conservative survival; the measured start state may still offer attacks that leave two energy, but should remove a suicidal immediate end turn. A synthetic after-one-Toxic case should reserve the remaining one energy. High-HP and no-Toxic controls must not exclude attacks. The guard must keep at least one legal action and abstain from filtering a plausible immediate enemy kill or unknown action effect. Run existing native controller tests and report candidate IDs, exact tested commit, model/game/MCP versions and limitations. If these controls fail, close without merge. A later genuine full-run evaluation requires a separate preregistered issue/PR.

Expected environment for provenance: game v0.111.0, MCP v0.15.0, Jev `typesafe/jev-1.13-20260917`. This experiment runs local Python filtering only, so it will make zero Jev calls, zero game actions and no spend. Its outcome is execution/decision-filter compatibility, not battle or win-rate evidence.

Iteration 1 at SHA `4e75f12` added `rsi.status_guard.reserve_toxic_energy` to guided combat candidate filtering. It models end-turn block from existing block, native Plating amount and one Cloak Clasp block per retained card; it conservatively adds the Toxic `Damage` values as self loss. It reserves energy only when clearing some or all playable Toxic cards changes a projected lethal end turn into a surviving one. A known simple attack that cannot remove the visible attacker is excluded if it would spend that reserve; end turn is excluded, but unknown attacks are preserved. The initial `python3 -m unittest tests.test_toxic_reservation` and direct-file invocation failed due Python test-package import paths, not assertions. Running `python3 -m unittest discover -s tests -p 'test_toxic_reservation.py'` passed six tests and the full discovery command passed 65 tests. An exploratory candidate probe showed the measured after-Molten case narrowed to Toxic actions, but review found that a Vulnerable target could make nominal damage underestimated.

Iteration 2 at tested SHA `6b2d9baeae76ba125f01bdf237c3095a02dd72cf` conservatively abstained from filtering an attack against a Vulnerable target and added that control. Formal `python3 -m unittest discover -s tests` passed all 65 tests. On the frozen measured turn2 start, candidates changed from 13/13 baseline to 12/13 (only immediate end turn removed; Molten Fist still available). After actual Molten Fist, they changed from 11/11 baseline to 2/11, the two playable Toxic cards; historical Replay Strike `a002` is absent. A synthetic after-one-Toxic control kept only the remaining Toxic; high-HP/no-Toxic controls left attacks available, and plausible immediate kill/unknown effect/Vulnerable controls abstained. `result.json` records IDs and exact SHA. No native battle was replayed, so this is a supported candidate-safety improvement, not a proven battle or run win. Merge the narrow guard while keeping the full-run effect as a separate experiment; the status-versus-block trigger order remains unverified and the forecast is explicitly conservative.
