# E070 — suppress duplicate projected-loss review after a leased potion opener

Issue: [#132](https://github.com/yzxoi/RSI-Jev-Slay-the-Spire-2/issues/132). Baseline: merged `main` at `9810da2b30c7c589c5c1ce53f50e9c8fbd390720`. In E068's real Ironclad A0 floor-31 Hunter Killer turn 2, Astra's state-bound Flex Potion opener was accepted and `--review-lease` activated, but the controller immediately returned `expert_required` after one action and zero Jev calls. The potion did not increment `cards_played_this_turn`, so the independent projected-loss alert still appeared to be at turn start. Source raw trace SHA-256 `04e65ae94ae8fecc35bbf8e044aeab40309af75bb8e330ea26d9b5ac523c51f1`.

Hypothesis: a validated same-turn review lease may suppress this repeated projected-large-loss pause after an accepted expert opener, while the projected alert remains in trace. Without an explicit lease, baseline behavior is unchanged. A stale fingerprint, changed turn/run, unknown attack or unsafe retained self-loss must revoke the lease, and the hard lethal end-turn guard must remain independent.

Frozen input: [`frozen-potion-lease.json`](frozen-potion-lease.json) is a sanitized reduction of the E068 after-potion state at original full-state hash `c0dd4bfb72997d3f5fd6a46db3e83c4d66fddce367325cc158486e43c7d8a941`. Its read-only `review_projected_loss(state, 20)` reproduces the original alert exactly: 37 HP, 21 visible incoming, projected 16 HP. Baseline controller paused again despite the active lease. Test that the valid lease permits Jev continuation, that no lease and revoked lease still require review, that changed turn/stale hash/unknown attack revoke, and that a lethal end-turn still stops. Run full repository tests. This is a routing replay, not a combat simulation or win-rate result.

Decision: merge only if the frozen valid-lease case avoids exactly the duplicate pause, negative controls remain guarded, hard lethal end-turn remains guarded, and all tests pass. Native game write is not required for this read-only routing change; a later visible run can measure runtime cost. Do not infer any strategic strength improvement.

Implementation at tested SHA `d4f5e5c` added an explicit lease-aware projected-loss routing gate. It still computes and traces the same warning, but after the controller validates a same-turn lease it records `projected_loss_pause_suppressed` and continues to Jev. The accepted-action fingerprint, turn/run/scene, unknown-attack and self-loss checks in `ReviewLease.validate` remain unchanged. The existing hard end-turn review still runs immediately before delivery of any non-expert `end_turn`. Iteration `6871d39` added an unsafe retained Beckon self-loss control; no failed implementation was amended away.

At exact tested SHA `6871d39`, `python3 -m unittest discover -s tests -q` passed 112 tests. A deterministic replay of the sanitized E068 state reproduced the original projected-loss report exactly and verified its ignored raw source trace SHA-256. Without a lease the report still requires expert review; with the accepted, validated lease it suppresses one duplicate pause. New turn, stale fingerprint, unknown attack and unsafe retained self-loss each revoke the lease and restore review. A synthetic lethal end-turn remains blocked by the independent hard guard even when the lease is active. Compact verification is in [`result.json`](result.json).

Decision: merge the opt-in routing correction. It meets the frozen compatibility and safety controls, but there was no new native action and no battle outcome in E070. The measurable result is one avoided repeat request at the frozen E068 boundary, not improved win rate. The next visible run must confirm runtime behavior and keep the hard end-turn trace visible.
