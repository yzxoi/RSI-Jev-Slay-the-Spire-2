# E040 — One Astra plan per floor, Jev execution

Issue #71. The current controller delegates ordinary combat to an approximate hand planner and macro/potion decisions to Jev; a low-HP threshold can pause before checking a known kill. Test a different division of labor: Astra writes one compact plan at a map boundary, Jev chooses legal actions during the next room, and the native controller rechecks every action against fresh state. The plan is advice, not a forced command or game-state edit.

The first experiment tests protocol feasibility, not win-rate improvement. Baseline is the merged native `retaliate` controller without floor guidance. No simultaneous native baseline can run on the player's one live game, and an offline choice comparison would not establish a counterfactual run. E039 engine branches and E006 automatic Astra routing remain separate experiments.

Freeze exact start fingerprint and guidance before execution. One Astra strategic plan, at most 80 accepted actions, 300 controller seconds, $0.10 Jev. Stop at the next MAP on floor 8 after resolving room/rewards, genuine game over, or an explicit compatibility/safety boundary. The run is not restarted or edited. Preserve actual loss/stall if one occurs.

Protocol gate: the plan must bind run ID, start floor, next floor and exact initial state hash; it expires after the target map. Jev receives the plan in every discretionary request and a computed proposal in combat, while the native legality, freshness, single-writer and lethal-end-turn guards remain. Tests check stale plan rejection and boundary. Promote the protocol only if the tests pass, at least one real Jev request contains the plan, and the pilot has no plan-attributable illegal/stale execution or missed boundary. This does not prove stronger play. Measure Jev requests/cost, controller time, floor completion, HP, action count, plan adherence, and all stops.
